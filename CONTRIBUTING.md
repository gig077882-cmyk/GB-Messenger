# Участие в разработке

Спасибо за интерес к «Кругу / GB-Messenger».

## Перед началом

- Обсуждайте заметные изменения в issue или pull request до большой реализации.
- Не добавляйте в репозиторий секреты, рабочие `.env`, токены, ключи, сертификаты, provisioning profiles, резервные копии и пользовательские данные.
- Не меняйте поведение Docker Compose или CI без отдельного обоснования и проверки.

## Локальная проверка

Используйте Node.js 20+ и зависимости из lock-файлов:

```sh
npm ci --prefix backend
npm run check --prefix backend
npm ci --prefix frontend
npm run build --prefix frontend
npm test --prefix frontend
docker compose --env-file .env.validation config -q
```

Для полного стека создайте локальный `.env` из `.env.example` и замените все шаблонные секреты. `.env` не должен попадать в коммиты.

## Pull request

- Делайте изменения небольшими и сфокусированными.
- Кратко опишите цель, затронутые компоненты и выполненные проверки.
- Обновляйте документацию, если меняются настройка, эксплуатация или пользовательское поведение.
- Сохраняйте совместимость с ограничениями MVP: один экземпляр backend и отсутствие E2EE.

Все участники обязуются соблюдать условия [лицензии MIT](LICENSE).
