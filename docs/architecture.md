# Круг — архитектура семейного мессенджера

## Цели первой версии

- До 60 семейных пользователей, доступ через интернет по HTTPS.
- Личные и групповые чаты, сообщения, реакции, ответы, пересылка и статусы доставки.
- Временная передача файлов до 5 ГБ с возобновляемой загрузкой.
- Личные и групповые WebRTC-звонки максимум на 3 участников.
- Web/PWA и подготовленный общий API для будущего iOS-клиента (`.ipa`).
- TLS без сквозного шифрования. Оператор сервера технически может читать данные.

## Компоненты

- `backend`: Node.js, Fastify, WebSocket и SQLite в WAL-режиме.
- `frontend`: React, Vite, TypeScript, адаптивная PWA.
- `storage`: локальный Docker volume; файлы не помещаются в SQLite.
- `coturn`: резервный маршрут WebRTC.
- `caddy`: HTTPS, reverse proxy и раздача web-клиента.
- `backup`: консистентная копия SQLite и конфигурации по расписанию.

Redis, PostgreSQL и MinIO исключены из MVP ради экономии памяти. Backend запускается в одном экземпляре — это соответствует модели записи SQLite.

## Потоки данных

1. Клиент авторизуется и получает короткий access token и refresh cookie.
2. REST используется для истории, управления чатами и загрузок.
3. WebSocket доставляет сообщения, статусы, presence, typing и WebRTC signaling.
4. Вложение загружается частями; после сборки сервер выдаёт авторизованную ссылку.
5. Получатель подтверждает скачивание. Очистка удаляет истёкшие файлы.
6. Звонок до трёх участников использует mesh WebRTC; backend выполняет signaling.

## Лимиты

- 60 активных аккаунтов.
- 5 ГБ на файл, части по 8 МиБ.
- 300 ГБ суммарно под временные вложения.
- 3 участника звонка, включая инициатора.
- При остатке диска менее 50 ГБ новые загрузки блокируются.

## iOS

Web/PWA остаётся основным клиентом MVP. API и события не зависят от UI. Нативный iOS-клиент сможет использовать тот же API, APNs/PushKit, CallKit и WebRTC. TrollStore-сборка будет отдельным `.ipa`-артефактом только для совместимых версий iOS; push-возможности всё равно требуют корректных Apple entitlements.
